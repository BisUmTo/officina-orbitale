# Core arithmetic report
Implementati docs/core.mjs e tests/core.test.mjs. Sette test passati con Node locale: 16.384 somme esaustive (operandi0..127),256prodotti (0..15), conservazione di ogni fusione, normalizzazione e risultati, parziali inclusi bitzero, input immutabile, malformati, errori, replay e20missioni.
API spec rispettata. Dettagli integrazione: phase diventa completed con submit corretto; altre azioni restituiscono correct:false reason completed. Malformati lanciano TypeError/RangeError; replay non li converte in errori matematici. Shift accetta0..3 come contratto del gioco. Campagna e allenamento devono usare moltiplicatori b<=15: makeProblem accetta comunque operandi più ampi quando il risultato<=255, ma la risoluzione guidata per moltiplicatori oltre15 non è supportata. Allineamento irrilevante quando il valore del parziale è zero, inclusa copia del moltiplicandozero. firstTry richiede completamento, zero errori e un solo submit; independent significa zero hint. Nessuna normalizzazione obbligatoria nel core.
